# Unity Playmode Debugger 가이드

본 스킬이 활성화되면 에이전트는 유니티 에디터의 컴파일 상태를 점검하고, 플레이모드를 실행하여 발생하는 에러를 수집하고 해결하는 과정을 자동 수행한다.

## [프로세스 단계]

### 1단계: 컴파일 상태 점검
- `unity-mcp-server`의 `refresh_assets` 도구를 실행하여 변경된 코드 애셋을 반영시킨다.
- `get_compilation_state` 도구를 호출하여 스크립트에 컴파일 에러가 남아있는지 확인하고, 에러가 있다면 디버그하여 컴파일을 완료시킨다.

### [안전 가드: 무한 루프 사전 검사]
- 플레이모드로 진입하기 전, 새로 추가되거나 수정된 C# 코드 내의 `while` 및 `for` 루프에 명확하고 예외 없는 탈출 조건이 설정되어 있는지 정적 분석(코드 리뷰)을 필수로 수행한다. 무한 루프 위험이 있을 경우 플레이모드를 진입하지 않고 코드를 즉시 보완한다.

### 2단계: 플레이모드 구동 및 로그 수집
- 컴파일 에러가 없다면 `play_game` 도구를 호출하여 유니티 에디터를 플레이모드로 진입시킨다.
- **[비동기 로딩 대기 조건]**: Project109는 시작 시 `AssetCacheManager`가 Addressables 및 `ModLoader`를 비동기로 로드한다. 따라서 단순히 고정 시간만 대기하지 말고, 콘솔에 `"All Data Load is Complete."` 로그가 출력되었는지 확인하거나 **최소 3~5초 이상 충분히 대기**한 뒤 `read_console`을 호출한다.
- `read_console` 도구를 주기적으로 호출하여 콘솔 창에 찍히는 로그들을 모니터링한다.
- 특히 `Error`, `Exception`, `Assertion` 등 프로그램 비정상 종료나 오작동과 연관된 심각한 콘솔 오류를 우선적으로 필터링한다.

### 3단계: 디버깅 및 자율 수정
- 수집된 에러 콘솔 로그의 Callstack을 분석하여 원인이 된 클래스와 코드 라인을 식별한다.
- 에디터를 플레이모드에서 빠져나오게 하기 위해 `stop_game`을 호출한다.
- 에러의 원인이 되는 코드를 수정하고, 다시 1단계부터 진행하여 디버깅이 완결되었는지 검증한다.
- **[무한 재시도 방지 가드]**: 동일한 에러 또는 연쇄 에러로 인해 [1단계~3단계] 루프가 **최대 3회** 반복되어도 해결되지 않을 경우, 즉시 자율 수정을 중단(`stop_game`)하고 현재까지의 분석 로그와 시도한 수정 내용을 사용자에게 상세히 보고하여 추가 지시를 받아라. 무한 루프로 코드를 훼손하거나 토큰을 소모하는 것을 엄격히 금지한다.
