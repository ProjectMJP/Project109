# Mermaid 다이어그램 작성 규칙 (Mermaid Diagram Syntax Rule)

Mermaid 다이어그램을 Markdown 문서 또는 아티팩트에 작성할 때는 마크다운 렌더러(GitHub, IDE 뷰어 등)의 구문 파싱 에러(`Parse error`)를 방지하기 위해 반드시 아래 규칙을 엄격히 준수한다.

---

## 0. 예시 코드 블록 표기 주의사항 (문서 작성 시 필수)

- **오류 예시나 단편적인 스니펫에는 절대로 ` ```mermaid ` 코드 블록을 쓰지 않는다.**
  - IDE의 Markdown 프리뷰어는 ` ```mermaid ` 블록을 감지하는 즉시 렌더링을 시도하므로, 미완성 스니펫이나 잘못된 문법이 들어가면 문서 뷰어 자체에서 파싱 에러 팝업/경고가 발생한다.
  - 잘못된 예시나 부분 문법은 반드시 ` ```text ` 또는 ` ```csharp ` 등으로 감싼다.
  - ` ```mermaid `는 **선언문(`flowchart TD` 등)부터 완벽히 갖추어져 단독으로 즉시 렌더링 가능한 완전체 블록**에만 사용한다.

---

## 1. 노드 ID 및 서브그래프(Subgraph) ID 규칙 (가장 중요)

- **ID에는 절대 공백, 한글, 특수문자를 넣지 않는다.**
  - 오직 **영문 알파벳, 숫자, 언더스코어(`_`)**만 사용한다 (`[a-zA-Z0-9_]+`).
- **화면에 표시할 한글, 공백, 특수문자는 반드시 큰따옴표(`"..."`)로 감싼 라벨에 작성한다.**
  - ❌ **오류 발생 스니펫** (ID에 공백/콜론 포함):
    ```text
    subgraph Phase 1: 안전성
    Phase 1 --> Phase 2
    Node A --> Node B
    ```
  - ⭕ **올바른 완전체 다이어그램**:
    ```mermaid
    flowchart TD
        subgraph P1 ["Phase 1: 안전성 및 코드 위생"]
            P1_1["1. 빌드 가드 추가"]
        end
        subgraph P2 ["Phase 2: 구조 개선"]
            P2_1["2. 중복 코드 제거"]
        end

        P1_1 --> P2_1
    ```

---

## 2. 라벨 텍스트와 특수문자 규칙

- 라벨에 콜론(`:`), 괄호(`()`, `[]`, `{}`), 슬래시(`/`), 쉼표(`,`) 등이 포함될 경우 파서가 문법 기호로 오인하므로 **반드시 큰따옴표(`"..."`)로 전체를 감싼다.**
  - ❌ **오류 발생 문법**:
    ```text
    A[버전 1.0 (안정화): 완료]
    B[10/10 달성]
    ```
  - ⭕ **올바른 문법**:
    ```text
    A["버전 1.0 (안정화): 완료"]
    B["10/10 달성"]
    ```
- 라벨 내부에서 큰따옴표(`"`)를 직접 사용해야 할 때는 작은따옴표(`'`)나 백틱(`` ` ``)으로 대체한다.

---

## 3. 서브그래프(Subgraph) 간 연결 규칙

- 렌더러 호환성을 위해 **서브그래프 자체를 연결하는 구문(`subgraphA --> subgraphB`)은 지양**하고, **서브그래프 내부의 마지막 노드와 다음 서브그래프의 첫 번째 노드를 직접 연결**한다.
  - ❌ **오류 위험**:
    ```text
    Phase 1 --> Phase 2
    ```
  - ⭕ **권장 방식**:
    ```text
    P1_LastNode --> P2_FirstNode
    ```

---

## 4. 다이어그램 선언 및 화살표 규칙

- 다이어그램의 첫 줄에는 반드시 명확한 종류와 방향을 선언한다.
  - Flowchart: `flowchart TD` (상하) 또는 `flowchart LR` (좌우)
  - `graph`보다는 최신 문법인 `flowchart`를 우선 사용한다.
- 화살표 텍스트에 공백이나 특수문자가 들어갈 때도 파싱 에러를 유의한다:
  - ⭕ `A -->|"성공 (200 OK)"| B`
